# Revisión de riesgos de integración local

**Fecha:** 26 de octubre de 2026. **Alcance:** revisión técnica del flujo local y preparación de gates; no constituye aprobación para producción ni aceptación de riesgos por el responsable. Los entornos/DB productivos no se probaron.

| Área | Evidencia/controles verificados | Riesgo residual | Estado antes de release |
|---|---|---|---|
| Google ID token | Verificador oficial probado con firma RS256 local; firma, issuer, audience, expiración, nonce, email verificado y replay se rechazan/verifican. Contratos cubren `hd`, dominio UCB exacto, allowlist y estados de cuenta. | No se completó login humano en esta sesión; falta verificar orígenes, test-user/publicación del proyecto Google y el callback visual en ambos sitios. | Bloquea aceptación OAuth. |
| `ADMIN_EMAILS` y roles | Variable leída solo por backend; comparación de email normalizado y grants a ambos eventos transaccionales/idempotentes. Archivo local ignorado por Git. Contratos cubren asignación y cuentas no activas. | No se observó asignación ADMIN con una cuenta humana real. El acceso a la consola/gestor de secretos del servidor aún no se configuró. | Provisionar de forma controlada en el entorno final. |
| Correo e invitaciones | API local envió la invitación a Mailpit; enlace apuntó a Innovation Week, TTL de tres días, hash de token persistido y datos/message sintéticos retirados. Falla SMTP conserva whitelist/token y se expone a la UI. | No hay proveedor SMTP externo configurado ni prueba de entrega a destinatario real. No existe reenvío; un fallo requiere intervención operacional según el alcance actual. | Bloquea entrega real y release con invitaciones. |
| CORS y orígenes | Backend local permitió exclusivamente los orígenes configurados `localhost:3000` y `localhost:5173`; challenge respondió 200 y los frontends 200. | Dominios HTTPS finales aún no están asignados; no se ha validado el gateway ni configuración CORS en el servidor. | Añadir/validar orígenes al configurar dominios. |
| Rate limits | Límites separados para challenge/login, email proof, invitación y consumo; almacenamiento compartido mediante Redis. | Límites no se han ajustado con tráfico observado ni bajo abuso en servidor. Protección de edge/WAF no forma parte del entorno local. | Revisar umbrales y Redis en staging/servidor. |
| PII, tokens y auditoría | Contratos minimizan datos devueltos; credenciales/tokens no se registran explícitamente en los handlers revisados; pruebas/smoke usaron identidades sintéticas. RF-514 conserva auditoría existente fuera de este flujo. | La fase funcional omite auditoría para vínculo Google, whitelist, invitación y cambios de scope por decisión del responsable. Falta aprobación/enmienda constitucional antes del release; revisar telemetría/logs del entorno final. | Gate constitucional y revisión de logs abiertos. |
| Separación/migraciones | 29 migraciones pasaron dump/restauración local; se verificaron ledger/hash, FKs y uniques compuestas, filas TEDx legacy y cero huérfanos. RF-119 quedó protegido ante revocación y deshabilitación concurrentes por un advisory lock transaccional compartido. No se accedió a Supabase productivo. | El fixture no acredita compatibilidad entre versiones ni despliegue online sin bloqueo. La base destino del servidor/estrategia de backup/cutover aún no está elegida. | Resolver T031 y ensayar con dump sanitizado del destino aprobado. |
| Avatar 2D | Servicio local valida bridge firmado de 90 segundos, scopes `claim`/`revoke`, expiración, replay y ownership; API/editor responden 200. | No se completó un recorrido visual con cuenta Google real ni persistencia en el servidor final. | Coordinar proxy/host/storage del servicio en el deploy. |
| Fallback de contenido | Ambos frontends conservan datos de muestra cuando no hay conexión o las listas llegan vacías; el panel no ofrece IDs de muestra para escritura. Pruebas de front y smoke local. | Puede verse contenido editorial de demostración; la agenda real requiere aprobación de contenido y fecha completa antes de sembrarse. | Confirmar etiquetas de demo y contenido aprobado antes de abrir inscripciones. |
| Dependencias | Revisión previa documenta cero vulnerabilidades de producción en backend/Innovation Week y siete advisories de dependencias de desarrollo en TEDx. | Este registro no vuelve a ejecutar auditorías de paquetes; hay que revalidar dependencias y lockfiles antes de release. | Repetir auditoría al congelar el release. |

## Decisiones aún abiertas

- Definir si los campos de perfil académico (facultad/carrera/consentimiento) se comparten globalmente o se guardan por evento antes de cambiar el esquema (T001). La implementación actual conserva el perfil global.
- Confirmar mes y año del calendario entregado antes de guardar timestamps de programa; los días/horas por sí solos no fijan una fecha.
- Confirmar owner del proyecto Google, estado del consent screen, orígenes de los dominios finales y test users (T007/T067).
- Completar login humano Google, SMTP externo, revisión constitucional RF-514, revisión de dependencias y plan Docker/servidor aislado antes del gate de release (T052/T067/T068/T071/T072).

La matriz requisito→código→prueba está en [trazabilidad-requisitos.md](./trazabilidad-requisitos.md); el procedimiento de release está en [plan-deploy-servidor-aislado.md](../../docs/plan-deploy-servidor-aislado.md). Esta revisión registra evidencia y controles, pero no declara aceptación de riesgos productivos.
